Compatibility

This plugin is compatible with IntelliJ IDEA 2025.1 and above.
If you are using older versions (2023.2 up to 2025.1), please consider updating IntelliJ or contact hotrocntt (MB Bank IT Support) to request an upgrade.

About

This plugin is built specifically for the MB Bank App’s Automation Team, focusing on improving the workflow for Karate Framework API and functional testing projects such as Auto App KHCN.

Installation

  1. Download the mb-plugin.zip package or install directly from the internal plugin marketplace.
  2. Ensure you have the official Gherkin and Cucumber for Java plugin installed (required for .feature file support).
  3. Restart IntelliJ IDEA to activate the plugin.

Usage

  1. Syntax Highlighting & Formatting:
    Standard Gherkin syntax highlighting, code folding, and formatting are supported. No custom syntax extensions are added — the plugin builds upon native Gherkin/Cucumber behavior.
  2. Jira Issue Integration:
    Any tag following the pattern @MBA-XXXXX is automatically detected. A small Jira icon appears in the gutter; clicking it opens the corresponding issue in your default browser.
    Configure Jira under Settings → Tools → Jira Integration by specifying your Jira base URL and ticket pattern.
  3. Navigation & References:
    - Ctrl/Cmd + Click supports native Go to Step Definition for Gherkin steps.
    - call read('classpath:...') navigation is enhanced — you can jump directly to the target scenario in another feature file. Also applies for target json file
    - Missing or invalid feature paths are underlined and annotated for quick fixes.
  4. DocView (Documentation Hover):
    Hover over a call read statement to see its documentation if the target scenario includes a docstring such as:
     
            @tag 
            Scenario: Example 
            """ 
            @tag_DOC 
            This is the documentation for the scenario. 
            @param {required}{input} userId 
            User ID used for login 
            @return token Generated authentication token 
            """
    The plugin automatically parses
    @param (will trigger param check on call read() if tag {required} and {input} are involved, also autocomplete),
    @short allow defining a one-liner summary for the scenario that can be referred to as "short",
    @return,
    @snippet_before (will trigger autocomplete, the code snippet will be added before the call read()),
    @snippet_after (same but after call read()) tags
    and displays them in a structured view with syntax highlighting.
  5. Autocomplete:
    - Native Cucumber step autocompletion.
    - # triggers file path and scenario completion (e.g., typing #auth suggests auth.feature).
    - ! triggers tag-based completion (e.g., typing !login suggests all @login scenarios).
    - & triggers short-based completion (e.g., typing &create suggests scenarios with @short create ...).
    - Parameter hints from @param directives in docstrings are also included in completions. Params which are defined with tag {required} and {inpit} will be subjected to be in autocomplete
    - snippet_before/after snippet content will also be added upon autocompletion.
  6. Enhanced Docstring Parsing:
    The plugin supports structured documentation blocks inside triple quotes ("""):
    • @param {tags} name — defines parameters with multiple tags (e.g., {required}{input}).
    • @return name — defines output variables.
    • @snippet_before / @snippet_after — defines Karate code snippets shown in DocView.

    The tag will affect how the parameter is treated ({required}{input} triggers error checking, shows in autocomplete).
  7. Error Checking:
    - Detects missing required @param inputs in call read(...) blocks.
    - Warns when a referenced feature or tag cannot be resolved.
  8. Custom Test Execution:
    A custom gutter icon appears next to scenario tags. Clicking it allows you to Run or Debug a test through an auto-generated TestRunner.java file.
    You can configure multiple runner templates under Settings → Tools → Karate Test Runner:
    • Define multiple runner configurations (e.g., local, SIT, UAT).
    • Each runner template supports variable placeholders:
      • {{PACKAGE_NAME}}
      • {{CLASS_NAME}}
      • {{FILE_PATH}}
      • {{TAG_TEXT}}
  9. Import cUrl:
    Right-clicking inside a feature file now shows an "Import cUrl" option. Selecting this opens a dialog where you can paste a cUrl command. The plugin will parse the command and generate the corresponding Karate syntax, inserting it and replace the file content
  10. Karate Tree Explorer
    A dedicated tool window displays a hierarchical tree view of all Karate feature files in your project.
    Features include:
    - Expand/collapse directories to navigate feature files.
    - Click on scenarios to jump directly to their definitions in the editor.
    - The tree view automatically updates when feature files are added, removed, or modified.
    There is a choice to view scenarios being call read by their short description (if any) or by their original call read line.
  11. Short Playbook:
    List all short definitions across the project in a dedicated tool window for quick reference and navigation.
    The user can search for specific short definitions using a search bar at the top of the window.
  12. GUI Edit Examples Table:
    For Scenario Outlines with Examples: blocks, a spreadsheet icon appears in the gutter next to the Examples: keyword.
    Clicking the icon opens a tool window on the right with an Excel-like table editor where you can:
    • Add or remove columns and rows
    • Edit cells directly
    • Copy and paste values from Excel or other sources (Ctrl+V)
    • Delete cell contents with Delete or Backspace keys
    The Examples table in your feature file updates in real-time as you edit the spreadsheet, with automatic formatting (similar to Ctrl+Alt+L).
    Works with both empty Examples: declarations and existing tables.
